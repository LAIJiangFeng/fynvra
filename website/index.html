Fynvra 是本地桌面 AI 编程工作台：主 Agent 拆解需求，为每个任务开一个独立 git worktree，交给 Worker 并行执行；再由主 Agent 读改动、跑检查、验收合并

Fynvra is a local desktop workbench for AI coding. The orchestrator splits your request and gives every task its own git worktree and worker. When the work comes back, it reads the diff, runs the checks, and merges what passes.

02 Workflow / 工作流

从一句需求，到一次干净的合并 From one request to a clean merge

派发、执行、审查、合并都在同一个窗口里完成；每一步都是可追踪的工具调用，下方窗口与数据为结构示意

Dispatch, execution, review, and merge happen in one window — every step is a traceable tool call. Screens and values below are illustrative.

01

Orchestrator

只派活，不动手It delegates, it doesn’t edit

默认主 Agent 使用编排工具策略：可以读文件、执行只读 git、派发与验收，但不能写文件或执行任意命令；派发后它不会阻塞等待，收件箱有消息时再由 Fynvra 唤醒

The default orchestrator gets read-only and orchestration tools: read files, read-only git, dispatch, review, merge. No file writes, no arbitrary commands. It never blocks after a dispatch — Fynvra wakes it when the inbox has news.

02

Worktrees

每个任务，自己的目录与分支A directory and branch per task

每个 Worker 绑定一条 fynvra/<slug> 分支和独立 worktree；并行的 Agent 不会互相踩踏，主仓库在验收前保持原样；worktree 根目录可以配置

Every worker gets a fynvra/<slug> branch and its own worktree. Parallel agents never collide, and your main checkout stays untouched until review. The worktree root is configurable.

WORKTREESgit
├─repo/main
├─login-race/fynvra/login-race
├─ci-cache/fynvra/ci-cache
└─e2e-tests/fynvra/e2e-tests
默认位置Default root<repo>-worktrees
03

Review & merge

检查通过，才进入主分支Merged only after it passes

Worker 汇报后，主 Agent 读 diff、跑检查命令，再决定合并或打回；合并统一使用 --no-ff，随后清理 worktree；已合并的改动仍可回看

When a worker reports back, the orchestrator reads the diff, runs checks, then merges or sends the work back. Merges use --no-ff and clean up the worktree; merged diffs remain viewable.

Files open in center tabs beside the chat, a real terminal runs in the workspace, and every task’s changes are kept per attempt.

Text editing up to 256 KiB, Markdown edit / preview / split views, and version checks on save so conflicts keep both disk content and your draft.

A main-process PTY keeps running when you switch tabs or workspaces, and closing a terminal tab asks first.

08 FAQ / 常见问题

装之前，先看这些 Before you install

更完整的步骤与边界说明在使用文档

The full steps and boundaries live in the user guide.

Fynvra 和 Claude Code、Codex 这类 CLI 有什么不同How is Fynvra different from CLIs like Claude Code or Codex?

它们通常是单个 Agent 的命令行工具；Fynvra 是桌面工作台，内置基于 pi SDK 的运行时，把主 Agent 编排、worktree 隔离、消息收件箱、审查与合并做成完整流程；已有的模型服务和 MCP 配置可以导入

They are usually single-agent CLIs. Fynvra is a desktop workbench with a pi SDK-based runtime that ties orchestration, worktree isolation, an inbox, review, and merge into one flow. Existing provider and MCP configs can be imported.

收费吗，模型费用怎么算Is it free? How is model usage billed?

Fynvra 本身免费开源，使用 Apache-2.0 许可证；模型调用费用与额度来自你连接的服务商账号

Fynvra is free and open source under Apache-2.0. Model usage is billed by whichever provider account you connect.

我的代码和 API Key 会被上传吗Do my code and API keys leave my machine?

Fynvra 没有中转服务器，对话请求只发往你配置的模型服务地址；密钥明文只在主进程使用，但保存在本地配置文件中，不是加密凭证库，请不要分享应用数据目录

There is no relay server; prompts go only to the provider endpoints you configure. Plaintext keys are used only in the main process but stored in local config files — not an encrypted vault — so do not share the app data folder.

主 Agent 会自己改代码吗Will the orchestrator edit code itself?

默认不会，内置 Orchestrator 使用编排工具策略，只能读文件、执行只读 git 和调用编排工具，不能写文件或执行任意命令；你可以在角色设置里调整

Not by default. The built-in Orchestrator uses the orchestration tool policy: read files, read-only git, and orchestration tools — no writes or arbitrary commands. You can change it in role settings.

没有 git 的项目能用吗Can I use it without git?

能，普通文件夹按原地模式工作：不建 worktree，Worker 直接在目录里修改，审查时列出它汇报的改动文件；并行 Worker 会共用目录，建议一次只派一个任务

Yes. Plain folders run in place: no worktree, workers edit the folder directly, and review lists the files they reported. Parallel workers share the directory, so dispatch one task at a time.

支持哪些平台Which platforms are supported?

Windows x64 和 macOS（Intel / Apple Silicon），Linux 有 AppImage 构建配置，但尚未纳入自动发布与更新

Windows x64 and macOS (Intel and Apple Silicon). Linux has an AppImage build config but is not part of automated releases or updates yet.

Worker 会不会 push 代码或删库Can a worker push code or wipe my repo?

git push、git reset --hard、rm -rf 等保护操作在任何审批档位下都需要你确认，「本会话都允许」也不会豁免

Protected operations such as git push, git reset --hard, and rm -rf need your confirmation in every approval mode. “Allow for session” does not exempt them.

怎么更新 FynvraHow do updates work?

Windows 安装版与正式签名的 macOS 版会检查并后台下载稳定新版本，下载完成后由你确认安装；未签名的 Mac 包需要从 Releases 手动覆盖，开发模式不联网更新

Installed Windows builds and Developer ID-signed macOS builds check for and download stable updates, then wait for you to confirm the install. Unsigned Mac builds are replaced manually from Releases. Dev mode does not update online.
