Fynvra 是开源的桌面 AI 编程工作台。主 Agent 把你的需求拆成任务，为每个任务开一个独立的 git worktree 交给 Worker，再审查改动、运行检查、验收合并。你只需要说清楚要做什么。

Fynvra is an open-source desktop workbench for AI coding. The orchestrator splits your request into tasks, gives each one its own git worktree and worker, then reviews the diff, runs the checks, and merges what passes. You just describe the goal.

01能力Capabilities

把一句需求，变成一条可验收的流水线。Turn one request into a pipeline you can review.

主 Agent 负责拆解和派发，Worker 在各自的工作树里执行，最后统一审查、跑检查、合并。每一步都是可回看的工具调用，不是黑箱。

The orchestrator splits and dispatches. Workers execute in isolated worktrees. Review, checks, and merge come back to one place — every step a tool call you can inspect.

Orchestrator

主 Agent 只派活，不动手。An orchestrator that delegates.

默认的主 Agent 只有只读工具和编排工具：拆任务、派发、回答 Worker 的提问、验收合并。派发之后它不会干等，你可以接着讨论下一件事；收件箱一来消息，Fynvra 就把它叫醒。

The default orchestrator gets only read-only and orchestration tools. It plans, dispatches, answers workers, reviews, and merges. It never idles after a dispatch — keep talking, and Fynvra wakes it when the inbox has news.

  1. 拆解与派发Split and dispatch 把目标拆成互不依赖的任务，为每个任务建 worktree。 Turn the goal into independent tasks, each with its own worktree.
  2. 并行执行Build in parallel Worker 在各自分支里改文件、提交；卡住与完成都回到收件箱。 Workers edit and commit on their own branches; questions and results return to the inbox.
  3. 验收与合并Review and merge 审查改动、运行检查；通过后 merge --no-ff，不达标就退回重做。 Review the diff and run checks. Merge with --no-ff when it passes; send it back when it doesn't.

02工作流Workflow

从一句需求，到一次干净的合并。From one sentence to a clean merge.

派发、执行、审查，然后打回或合并，每个环节都是一次工具调用，都留有记录。合并统一走 --no-ff，主分支历史一目了然。

Dispatch, execute, review, then reject or merge — every step is a tool call with a record. Merges always use --no-ff, so your main branch history stays readable.

  1. 01

    说需求Describe

    在 Orchestrator 会话里说清目标、约束和要交给谁；不需要先写命令。

    Tell the orchestrator the goal, the constraints, and who should handle it. No commands required.

    chat
  2. 02

    派发Dispatch

    dispatch_task 建 worktree、启动 Worker、投递任务书；互不依赖的任务可以并行。

    dispatch_task creates a worktree, starts a worker, and hands over the brief. Independent tasks run in parallel.

    dispatch_task
  3. 03

    执行Build

    Worker 在自己的分支上改代码、提交。卡住用 ask_coordinator 提问，做完用 report_done 汇报。

    Workers code and commit on their own branches, ask_coordinator when stuck, and report_done when finished.

    ask_coordinator · report_done
  4. 04

    验收Review

    主 Agent 用 review_diff 读改动、run_checks 跑检查；不达标就 reject_work 打回重做。

    The orchestrator reads the diff and runs the checks; anything short of the bar goes back via reject_work.

    review_diff · run_checks
  5. 05

    合并Merge

    merge_worktree 合入当前分支，cleanup_worktree 收尾，再把结果和证据汇报给你。

    merge_worktree lands it, cleanup_worktree tidies up, and you get a report with evidence.

    merge_worktree · cleanup

运行时护栏Runtime guardrails

密钥只在主进程Keys stay in the main process

API Key、MCP 环境变量和请求头的明文不会通过 IPC 回到界面。

Plaintext API keys, MCP env vars, and header values never cross IPC to the UI.

没人回应，就是拒绝Silence means no

审批请求 10 分钟没有答复，或回合被中止，一律按拒绝处理。

Approval requests left unanswered for 10 minutes, or cut off by an aborted turn, are denied.

文件访问有围栏Fenced file access

读写限定在登记的工作区内，界面只传不透明 id，越界链接一律拒绝。

Reads and writes stay inside registered workspaces; the UI passes only opaque ids, and out-of-bounds links are refused.

本地运行，直连服务Local, with direct connections

Fynvra 没有中转服务器，模型请求直接发往你配置的服务地址。

There is no relay server; model requests go straight to the endpoints you configure.

04常见问题FAQ

装之前，先看看这些。Before you install.

更完整的说明见For the full picture, read the 使用文档user guide。.

Fynvra 和 Claude Code、Codex 这类 CLI 有什么不同？How is Fynvra different from CLIs like Claude Code or Codex?

Claude Code、Codex 是单个 Agent 的命令行工具。Fynvra 是桌面工作台，内置基于 pi SDK 的 Agent 运行时，把主 Agent 编排、worktree 隔离、收件箱、审查和合并做成一个完整流程。你在这些工具里配好的模型服务和 MCP 服务器可以直接导入。

Claude Code and Codex are single-agent CLIs. Fynvra is a desktop workbench with its own pi SDK–based agent runtime that ties orchestration, worktree isolation, an inbox, review, and merge into one flow. The providers and MCP servers you set up in those tools can be imported directly.

收费吗？Is it free?

Fynvra 本身免费开源，使用 Apache-2.0 许可证。模型调用的费用和额度来自你自己的服务商账号。

Fynvra itself is free and open source under Apache-2.0. Model usage is billed by whichever provider account you connect.

我的代码和 API Key 会被上传吗？Do my code and API keys leave my machine?

Fynvra 在本机运行，没有中转服务器，对话请求只发往你配置的模型服务地址。密钥明文只在主进程使用，但目前保存在本地配置文件中，并不是加密凭证库，请不要分享应用数据目录。

Fynvra runs locally with no relay server; prompts go only to the provider endpoints you configure. Plaintext keys are used only in the main process, but they are stored in local config files — not an encrypted vault — so don't share your app data folder.

主 Agent 会自己改代码吗？Will the orchestrator edit code itself?

默认不会。内置的 Orchestrator 使用「编排」工具策略，只能读文件、执行只读 git 和调用编排工具，不能写文件或执行任意命令。你可以在角色设置里调整。

Not by default. The built-in Orchestrator uses the Orchestration tool policy: it can read files, run read-only git, and call orchestration tools, but it can't write files or run arbitrary commands. You can change this in role settings.

没有 git 的项目能用吗？Can I use it without git?

能。非 git 目录按原地模式工作：不建 worktree，Worker 直接在目录里修改，审查时列出它汇报的改动文件。并行的 Worker 会共用同一个目录，建议一次只派一个任务。

Yes. Folders without git run in in-place mode: no worktrees, workers edit the folder directly, and review lists the files they reported. Parallel workers would share the folder, so dispatch one task at a time.

支持哪些平台？Which platforms are supported?

Windows x64 和 macOS（Intel / Apple Silicon）。Linux 有 AppImage 构建配置，但暂未纳入自动发布与更新。

Windows x64 and macOS (Intel and Apple Silicon). Linux has an AppImage build config but isn't part of automated releases or updates yet.

Worker 会不会 push 代码或删库？Can a worker push or wipe my repo?

git push、git reset --hard、rm -rf 等保护操作，在任何审批档位下都需要你确认，「本会话都允许」也不会豁免。

Protected operations such as git push, git reset --hard, and rm -rf need your confirmation in every approval mode, and “Allow for session” doesn't exempt them.
