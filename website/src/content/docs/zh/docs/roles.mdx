角色是一套可复用的配置：提示词、模型、思考档位、工具策略、审批档位、技能、MCP 和指令文件。新建会话时选角色；主 Agent 派发任务时也按角色启动 Worker。

<span id="roles-edit" />

## 新建、复制与修改

在「设置 → 角色」里，左侧是角色列表和「新建 / 导入」按钮，右侧是编辑器。点列表中的角色切换；有未保存修改时会先确认是否放弃。导入读取 JSON 文件，id 冲突的角色会自动改名。

编辑器里可以改名称、描述、系统提示词、模型与思考档位、工具策略、审批档位、技能、MCP 服务器和指令文件。系统提示词追加在基础提示词之后，可以清空。保存后用于新启动的会话；已经在运行的会话不会重读角色配置。

内置角色可以直接改；「恢复默认」会还原提示词、模型、工具策略、审批、技能和 MCP 等配置，确认后再点保存才生效。右侧菜单还能「复制为新角色」「导出 JSON」或删除角色；内置角色的 ID 固定且不可删除。

<span id="roles-builtin" />

## 两个内置角色

| 内置角色 | 工具策略 | 默认审批 |
| --- | --- | --- |
| Orchestrator | 编排 | 完全放行 |
| Worker | 全部工具 | 自动接受编辑 |

<span id="roles-policy" />

## 工具策略与 ID

工具策略有三档：

- **全部工具**：可以读、写、执行命令。Worker 默认用这个。
- **只读**：不能改文件，也不能执行任意命令。
- **编排**：读文件、只读 git，以及派发、审查、合并等编排工具。不能写文件或执行任意命令。Orchestrator 默认用这个，所以即使审批是「完全放行」，它自己也不会改代码。

角色 ID 只能是小写字母、数字和连字符，不能以连字符开头或结尾，保存后不能改。派发时如果没有指定角色，用默认的 Worker。
