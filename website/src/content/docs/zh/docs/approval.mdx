<span id="approval" />

审批决定哪些工具调用需要你点允许。档位可以在输入框旁切换，也能存进角色作为新会话的默认值。无论档位如何，少数受保护操作始终需要单独确认。

<span id="approval-set" />

## 在哪里切换

输入框左下角、模型胶囊旁边的审批胶囊显示当前档位。点开是三项单选列表；也可以按 <kbd>Shift</kbd>+<kbd>Tab</kbd> 循环切换。角色设置里也有一份默认值，新建会话时带上。

会话运行中也能切，下一次需要审批的工具调用起生效；已在等待的请求仍按原样处理。

<span id="approval-modes" />

## 三档行为

| 档位 | 行为 |
| --- | --- |
| 全程审批 | 执行命令、编辑文件、写入文件、调用 MCP 都要你点允许。 |
| 自动接受编辑 | 文件编辑和写入自动通过，命令和 MCP 仍要审批。Worker 默认是这个。 |
| 完全放行 | 常规工具自动通过。Orchestrator 默认是这个，但它的工具策略仍然不能改代码。 |

档位只决定是否弹出审批，不扩大工具能力。工具策略仍然决定这个角色能不能写文件、执行命令或只读。

<span id="approval-respond" />

## 处理一次审批

有请求时，会话状态变成「等待审批」，输入框上方出现审批条。审批条显示类型（执行命令 / 编辑文件 / 写入文件 / MCP 工具）、标题和可展开的详情；一次显示一条，更多请求会标出剩余数量。

按钮有三个：「拒绝」不让这次调用继续；「本会话都允许」允许当前会话里同类的后续请求；「允许」只放行这一次。提交期间按钮禁用。其他工作区也在等待时，窗口顶部会出现「有 N 项操作等待你确认」，点「查看并处理」按会话集中处理，不会改变你当前正在看的会话。

<span id="approval-floor" />

## 保护底线

<aside class="docs-callout docs-callout-warn">

**始终确认**

`git push`、`git reset --hard`、`rm -rf` 这类保护操作，在任何审批档位下都要你确认。「本会话都允许」也不会豁免它们。

</aside>
