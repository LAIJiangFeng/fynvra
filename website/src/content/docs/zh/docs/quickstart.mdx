按下面五步操作，第一次使用就能完成“连接模型 → 挂入目录 → 新建会话 → 发出需求 → 查看改动”。每一步都对应界面上的实际按钮。

<span id="quickstart-provider" />

## 1. 连接模型服务

按 <kbd>Ctrl</kbd>+<kbd>,</kbd>（macOS 为 <kbd>⌘</kbd>+<kbd>,</kbd>）打开设置，进入「模型服务」。点「添加服务」，选择预设，或用自定义 OpenAI 兼容地址；填写 Base URL 和 API Key，拉取或手动添加模型 id，打开需要思考档位的模型的「推理」，保存。

回到主窗口，在输入框左下角能看到模型胶囊，说明服务已可用。详细字段见 [模型服务](/zh/docs/providers/)。

<span id="quickstart-workspace" />

## 2. 挂入一个工作区

在左栏「工作区」标题右侧点 **+**，或在空状态点「挂入目录」，然后选一个 Git 仓库（普通文件夹也可以）。工作区项会显示名称和路径；再次点击当前工作区会展开它的会话列表。要用独立 Git worktree 派发，仓库需要已有提交。

普通文件夹也能创建会话并派发 Worker，但会显示「无 git」，Worker 直接在目录里改，不建 worktree；同一目录一次只派一个任务。需要并行派发时请使用 Git 仓库。

<span id="quickstart-session" />

## 3. 新建会话并选角色

展开工作区后，在「会话」标题右侧点 **+**；也可以在中间点「新建会话」。弹层默认选中 Orchestrator（带皇冠标记），要单干可以直接选 Worker 或自定义角色。选好模型和可用的思考档位，点「创建」。

会话打开后，标题栏显示状态、角色和当前分支；底部输入框可以开始写需求。

<span id="quickstart-first" />

## 4. 发出第一条需求

用平时的语言写清楚目标，按 <kbd>Enter</kbd> 发送，<kbd>Shift</kbd>+<kbd>Enter</kbd> 换行。运行中按钮会变成「排队」，同时出现「停止」；消息和工具调用会依次出现在时间线上。

使用主 Agent 派发时，它会读代码、拆任务，右栏「任务」标签上出现任务数量，点进去可以看到任务卡片和进度。直接和 Worker 或自定义角色对话时没有派发这一步。

<span id="quickstart-review" />

## 5. 查看它做了什么

在右栏「任务」里点一张任务卡片，任务详情会显示任务书、依赖、尝试、消息和 Worker 输出。任务处于「待验收」或「已完成」且有 git 时，点「查看改动」会切到「改动」标签并打开这次任务的 diff。

派发任务时，主 Agent 会在对话里汇报审查和合并结果。如果需求不清楚，Worker 的提问会由主 Agent 带回对话；直接在输入框回答即可。

<aside class="docs-callout docs-callout-warn">

**worktree 派发条件**

要用独立 Git worktree 派发，需要一个已有提交的 Git 仓库，并且本机配置了 Git 用户名和邮箱。普通文件夹仍可创建会话和派发 Worker，但 Worker 原地修改，同一目录一次只派一个任务。Windows 上建议安装 Git for Windows；如果找不到 Bash，到「设置 → 通用」里指定 Windows 本地命令壳。

</aside>
