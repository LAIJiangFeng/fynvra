# Fynvra 产品定义

Fynvra 是一个基于 Electron 和 [pi](https://github.com/earendil-works/pi) SDK 的本地桌面 AI 编程工作台。
内置多 Agent 协作能力，将 worktree 隔离、任务派发、消息收件箱与验收合并整合为完整的开发流程。

## 核心思想

### 1. 多角色（Role）
每个 agent 会话都挂一个角色。角色 = 系统提示词 + 技能(Skills) + MCP 服务器 + 模型/思考档位 + 工具白名单 + 审批档位。
- 内置角色：`orchestrator`（默认主 agent，见下）、`worker`（默认普通 agent）。内置配置仅作参考，可直接修改提示词、技能、MCP、模型和策略并保存，也可恢复默认；id 固定且不可删除。
- 用户自定义角色：如「全栈开发工程师」「测试工程师」「代码审查员」。角色以文件形式存放，可导入导出。
- 没有指定角色时，派发出去的就是原生 `worker`。

### 2. 默认主 agent 只听人安排、只派活、不干活
默认 **Orchestrator（主 agent）** 使用编排工具策略，用户可以按需调整角色配置。默认主 agent：
- 把用户的需求拆成任务，为每个任务 **开一个 git worktree**，启动一个 worker agent（可指定角色；未指定则用 `worker`），把任务书发给它。
- **自己不改代码**：工具集被限制为只读（读文件、git 只读、orchestration 工具），不能写文件 / 执行任意 shell。
- **监控** worker：派发后不阻塞等待，可继续与用户对话；收件箱收到 `worker_done` / `question` / `escalation` 时由 Fynvra 自动唤醒主 agent，回答问题、验收结果。
- **验收合并**：worker 完成后读 diff、跑检查命令、判断是否达标；达标则把 worker 分支合并到主 agent 所在分支，再删 worktree；不达标则把意见发回让 worker 继续改。
- 向用户汇报每个任务的结果与证据。

### 3. Worker 在独立 worktree 里干活
每个 worker 会话绑定一个 worktree（分支 `fynvra/<task-slug>`）。worker 的工具：pi 默认编程工具 + `ask_coordinator`（阻塞提问）+ `report_done`（一次性汇报，带 succeeded/failed）。
worker 的审批档位随主 agent 派发时的当前档位；模型按角色配置，角色没配则用主 agent 当前的。主 agent 与 Worker 都执行真实工具审批：`supervised` 审批命令、文件写入/编辑与 MCP；`auto-edits` 自动接受编辑，命令与 MCP 仍需审批；`full` 放行普通操作，但 `rm -rf`、`git push` 等保护底线在任何档位都必须人工确认，会话内允许也不豁免。用户可允许一次、会话内允许或拒绝；超时、Stop、断连按拒绝处理。参数校验、角色白名单、路径边界、编排权限和真正的信息提问仍有效。

只移除 App 顶部跨会话的全局审批横幅及其详情弹窗（ApprovalAttention）；会话内审批卡、确认操作和三档权限选择保留。OS 桌面审批通知继续遵循通知偏好并按请求去重，实时审批不受普通通知的启动静默或合并节流影响，点击只定位会话，不授权执行。重启不会重放未执行的旧工具；源码修改不会热更新已安装应用或原进程里的待答复调用。

## Fast（优先服务）
支持的两种 OpenAI 协议（Responses / Chat Completions）模型可在会话模型选择器里开启 Fast：为请求附加优先处理参数，独立于思考档位，默认关闭、随会话保存。
标记只代表请求模式，不代表已确认实际服务档位：服务商可能拒绝或忽略，速度与费用由其决定并可能增加费用或用量；本功能不增加自动降级重发逻辑。

## 上下文自动压缩
通用设置可选择「pi 原生自动压缩（默认）」「Magic Context（插件）」或「关闭自动压缩」。原生模式沿用 pi 的自动触发与默认阈值；关闭只停用自动压缩，不改变模型的上下文上限，Fynvra 不提供手动压缩入口。
Magic Context 是随应用交付的压缩插件（固定版本，MIT）：历史分段、tag/drop、historian 与 `<session-history>` 注入由插件自己的 SQLite 管理，数据全部放在 Fynvra 应用目录，不读取或共享本机终端 pi / Magic 的配置与数据库。Historian 使用当前会话的模型与 Fynvra 已保存的鉴权，在会话进程内后台调用，不启动终端 pi，也不会把密钥写入配置或命令行；每次 historian 是一次额外模型请求，按当前会话模型计费，主会话与派发的 worker 都适用。换模型后旧 historian 会取消，下一次使用新模型；按当前模型窗口和输出上限，用保守字节估算切分完整历史块，不截断 XML。估算包含系统提示、输出和请求预留，但不能保证未知服务商模板或错误模型元数据下的绝对 token 上界。
Dreamer、Sidekick、跨会话记忆、自动搜索与语义 embedding 默认关闭，不会下载 embedding 模型。插件的 `ctx_*` 工具只操作它自己的上下文存储，不新增命令执行、工作区文件写入或网络能力；角色原有的工具权限、审批档位与编排语义不变。插件加载或存储初始化失败、context/historian 运行期最终失败（包括超时、结果验证失败或无进展）、或当前模型窗口装不下 historian 时，该会话交回 pi 原生压缩，界面显示一次可关闭的非阻塞提示；关闭状态按会话保存，切换会话不会互相影响。未查看该会话时按通知设置显示固定文案的桌面提醒（不伪装成工具操作，不标记失败、不等待确认，其他会话不受影响）。运行期不改写 pi jsonl 的原始对话；Stop/关闭会取消在途插件工作，失效后的结果不会再发布或注入，用户取消不算插件故障。回退提示不会打断本轮输入框灰字建议，也不会恢复旧轮建议。策略随会话创建读取，已有会话不热切换，更改在新会话或重启应用后生效；尚未进行真实长会话的现网压缩验证。

## 输入框回复建议
一轮 AI 回复正常结束后，输入框空闲且没有队列、审批、图片或未发送草稿时，Fynvra 会用当前会话模型额外生成至多一条简短的「用户下一句话」，以灰色剩余文字显示，不进入草稿、不占发送按钮。
按右箭头采纳为草稿并停在末尾，不自动发送；Esc 忽略本轮，普通输入不匹配即隐藏。建议跟随最近对话与用户语言，失败或没有明确建议时静默不显示；不写入对话历史，不改正常对话的工具、思考档位或 Fast。

## 一句话用户旅程
挂入仓库 → 在该仓库开一个 Orchestrator 会话 → 说「做 X，Y 用测试工程师角色」→ 侧栏出现多个 worker 卡片（各自 worktree、实时输出、状态）→ 主 agent 验收合并 → 用户在自己的浏览器/终端验证效果。

## 工程与安全边界
- 分层构建：electron-vite 三段构建，结合 Zustand、Tailwind 4、Biome 与 Vitest；应用元数据通过 settings.json 持久化。
- 进程隔离：明确 IPC 与 Agent Worker 的安全边界，会话 jsonl 为正文权威源（见 `AGENTS.md`）。
- 资源配置：统一管理 Providers、Skills 与 MCP，支持扫描导入本机工具配置。
- 任务验收：内置差异查看、三档审批与 worktree 验收合并流程。

## 明确不做（v1）
手机伴侣、远程节点、SSH 项目、语音、内嵌浏览器。
