# Fynvra 产品定义

Fynvra 是一个基于 Electron 和 [pi](https://github.com/earendil-works/pi) SDK 的本地桌面 AI 编程工作台。
内置多 Agent 协作能力，将 worktree 隔离、任务派发、消息收件箱与验收合并整合为完整的开发流程。

## 核心思想

### 1. 多角色（Role）
每个 agent 会话都挂一个角色。角色 = 系统提示词 + 技能(Skills) + MCP 服务器 + 插件 + 模型/思考档位 + 工具白名单 + 审批档位。
- 内置角色：`orchestrator`（默认主 agent，见下）、`worker`（默认普通 agent）。内置配置仅作参考，可直接修改提示词、技能、MCP、模型和策略并保存，也可恢复默认；id 固定且不可删除。
- 用户自定义角色：如「全栈开发工程师」「测试工程师」「代码审查员」。角色以文件形式存放，可导入导出。
- 没有指定角色时，派发出去的就是原生 `worker`。

### 2. 默认主 agent 只听人安排、只派活、不干活
默认 **Orchestrator（主 agent）** 使用编排工具策略，用户可以按需调整角色配置。默认主 agent：
- 把用户的需求拆成任务，为每个任务 **开一个 git worktree**，启动一个 worker agent（可指定角色；未指定则用 `worker`），把任务书发给它。
- **自己不改代码**：工具集被限制为只读（读文件、git 只读、orchestration 工具），不能写文件 / 执行任意 shell；例外只有用 `write_plan` 往 `.fynvra/plans/` 写计划文件，以及计划模式下用 `write_doc` 写 Markdown 文档（见「计划模式」）。
- **监控** worker：派发后不阻塞等待，可继续与用户对话；收件箱收到 `worker_done` / `question` / `escalation` 时由 Fynvra 自动唤醒主 agent，回答问题、验收结果。
- **验收合并**：worker 完成后读 diff、跑检查命令、判断是否达标；达标则把 worker 分支合并到主 agent 所在分支，再删 worktree；不达标则把意见发回让 worker 继续改。
- 向用户汇报每个任务的结果与证据。

在主 agent 会话的输入框里，开头或空白后输入 `/` 选工作流、`@` 选角色（↑↓ 移动，Enter / Tab 选中，Esc 关闭），插入 `/工作流名`、`@角色名`（名称含空格时写成 `@「名称」`），表示用这个工作流做或派给这个角色；消息里的这些写法显示成标签，原文不变。

### 3. Worker 在独立 worktree 里干活
每个 worker 会话绑定一个 worktree（分支 `fynvra/<task-slug>`）。worker 的工具：pi 默认编程工具 + `ask_coordinator`（阻塞提问）+ `report_done`（一次性汇报，带 succeeded/failed）。
worker 的审批档位随主 agent 派发时的当前档位；模型按角色配置，角色没配则用主 agent 当前的。主 agent 与 Worker 都执行真实工具审批：`supervised` 审批命令、文件写入/编辑、MCP、访问网络与插件工具；`auto-edits` 自动接受编辑，命令、MCP、访问网络与插件工具仍需审批；`full` 放行普通操作。`rm -rf`、`git push` 等保护底线在 `supervised` / `auto-edits` 下必须人工确认，会话内允许也不豁免；在 `full` 下由「设置 → 通用 → 危险操作需要确认」决定（默认关闭：全部自动执行，便于无人值守；开启后同样必须确认），已打开的会话立即生效。用户可允许一次、会话内允许或拒绝；超时、Stop、断连按拒绝处理。参数校验、角色白名单、路径边界、编排权限和真正的信息提问仍有效。

只移除 App 顶部跨会话的全局审批横幅及其详情弹窗（ApprovalAttention）；会话内审批卡、确认操作和三档权限选择保留。OS 桌面审批通知继续遵循通知偏好并按请求去重，实时审批不受普通通知的启动静默或合并节流影响，点击只定位会话，不授权执行。重启不会重放未执行的旧工具；源码修改不会热更新已安装应用或原进程里的待答复调用。

## Fast（优先服务）
支持的两种 OpenAI 协议（Responses / Chat Completions）模型可在会话模型选择器里开启 Fast：为请求附加优先处理参数，独立于思考档位，默认关闭、随会话保存。
标记只代表请求模式，不代表已确认实际服务档位：服务商可能拒绝或忽略，速度与费用由其决定并可能增加费用或用量；本功能不增加自动降级重发逻辑。

## 上下文自动压缩
通用设置默认选择「Magic Context」，也保留显式「pi 原生自动压缩」和「关闭自动压缩」。新设置、未设策略及非法磁盘值均使用 Magic，主会话、worker 和恢复加载一致；不会覆盖合法的 native/off 偏好。压缩照 oh-my-pi 按方法链依次尝试：Magic（若启用）→ shake（不调用模型，把较旧的大工具输出替换为可恢复的占位说明，从不删用户与助手文字）→ 稳健模型摘要（超长历史分窗折叠、单条超长消息截断、超窗减半重试、暂时错误退避重试），全部失败后再以更激进的阈值跑一轮。仍失败时不锁会话：显示非阻断错误并停止本轮自动继续，用户可以继续发消息，新消息会再次触发压缩；「重试上下文恢复」只用于旧版本留下的恢复锁。Magic 健康时禁用 pi 原生自动压缩；Magic 在某会话出错后，该会话静默改用回退链直到重载，不提示用户、不弹通知，只记诊断日志；恢复锁说明只对旧版本留下的恢复锁会话显示。原生模式沿用 pi 的自动触发、阈值与保留量；其总超时默认 10 分钟，可设 30 秒至 30 分钟，包含摘要请求和重试等待。关闭只停用自动压缩，不改变模型的上下文上限。Fynvra 不提供日常手动压缩入口，只有失败后的「重试上下文恢复」。运行态显示加载时策略、实际引擎与恢复状态；更改设置在新加载会话（含恢复重载）或重启后生效。当前上下文占用与累计用量分开，压缩后尚无新用量时显示未知。
Magic Context 是随应用交付的压缩插件（固定版本，MIT）：历史分段、tag/drop、historian 与 `<session-history>` 注入由插件自己的 SQLite 管理，数据全部放在 Fynvra 应用目录，不读取或共享本机终端 pi / Magic 的配置与数据库。Historian 使用当前会话的模型与 Fynvra 已保存的鉴权，在会话进程内后台调用，不启动终端 pi，也不会把密钥写入配置或命令行；每次 historian 是一次额外模型请求，按当前会话模型计费，主会话与派发的 worker 都适用。换模型后旧 historian 会取消，下一次使用新模型；按当前模型窗口和输出上限，用保守字节估算切分完整历史块，不截断 XML。估算包含系统提示、输出和请求预留，但不能保证未知服务商模板或错误模型元数据下的绝对 token 上界。
Dreamer、Sidekick、跨会话记忆、自动搜索与语义 embedding 默认关闭，不会下载 embedding 模型。插件的 `ctx_*` 工具只操作它自己的上下文存储，不新增命令执行、工作区文件写入或网络能力；角色原有的工具权限、审批档位与编排语义不变。插件未就绪、初始化失败、context/historian 最终失败（含超时、验证失败、无进展）、预算不足或服务商报告超窗时，该会话停用 Magic 并改用上述回退链继续，保留历史与 Magic 数据。会话内及桌面通知使用固定提示，不传 provider 原始错误，其他会话不受影响。以下恢复流程只适用于旧版本留下的恢复锁。修复服务或存储问题、必要时换用更大上下文模型后，点击「重试上下文恢复」会重新加载同一会话的 Magic，让 context 钩子重新整理和注入历史；旧 native 失败留下的恢复记录也走此路径，不调用原生摘要。有中断任务时才继续原轮次，完整恢复前不清恢复锁，已写入的输入通过隐藏的继续标记接续，未消费输入只提交一次，无需重新发送；暂时的网络错误仍允许 SDK 正常重试，以最终结算判断成败。若故障发生在空闲或尚无输入的初始化阶段，重试只校验实际上下文（空历史不造消息），校验成功后解锁，不请求模型继续已完成的工作。Stop/关闭会取消在途插件工作，失效后的结果不会再发布或注入；取消不算插件故障，也不自动继续。已有会话不热切换，未做真实长会话的现网压缩验证。

## 会话守护
「设置 → 通用」里的可选开关，默认关闭。开启后 Main 按检测间隔（15–1800 秒，默认 60）检查会话：主 agent（或「全部直接对话的会话」）因模型请求失败（网络中断、服务报错、限流，pi 重试用完之后）或 agent 进程崩溃而停在出错状态时，自动发一条标明「不是用户消息」的恢复消息让它先查状态（`list_workers`、待审查项）再继续，后续由现有编排流程接管。可选的「长时间无输出」触发（默认关闭，10–240 分钟，默认 30）：运行中、没有正在执行的工具却超过阈值没有任何事件时先中止这一轮再恢复；派发的 worker 卡住只中止，由编排报告给主 agent。
每个会话连续自动恢复有上限（1–50，默认 10），失败后的等待按次数翻倍（最长 30 分钟），一轮正常结束后计数清零。只在应用运行期间生效；不恢复用户点了停止的、已归档或已删除的会话，不直接恢复派发的 worker，不复活开启前或启动应用前的失败。每次恢复都是一轮新的模型请求，会产生费用。不做：阻止系统睡眠、桌面通知、工具执行超时检测、压缩失败的自动重试（仍走「重试上下文恢复」）。

## 输入框附件
输入框可以附图片和文档：点回形针按钮选择、粘贴或拖到输入框上。文档支持文本（代码、Markdown、CSV、JSON、日志等，自动识别 UTF-8、UTF-16 和 GBK/GB18030，容忍串口日志里零星的乱码字节）、PDF、Word `.docx` 和 Excel `.xlsx`（按工作表转成制表符分隔的文本），在本机抽出纯文字随消息发给模型（文件块在前、用户的话在后），只有附件没有文字也能发；消息里显示为文件标签，不显示文件内容，重新打开会话后一致。
上限：每条消息最多 10 个文件，单个文件不超过 32 MB，附件文字合计不超过 20 万字符。不支持旧版 `.doc` / `.xls`、PPT 和二进制文件，Big5、Shift-JIS 等其他编码的文本可能显示成乱码；扫描版 PDF 没有可读文字、加密或损坏的文件读不出来，都会给出提示。带附件时以 `/` 开头的命令不会被识别。

## 输入框回复建议
一轮 AI 回复正常结束后，输入框空闲且没有队列、审批、图片或未发送草稿时，Fynvra 会用当前会话模型额外生成至多一条简短的「用户下一句话」，以灰色剩余文字显示，不进入草稿、不占发送按钮。
按右箭头采纳为草稿并停在末尾，不自动发送；Esc 忽略本轮，普通输入不匹配即隐藏。建议跟随最近对话与用户语言，失败或没有明确建议时静默不显示；不写入对话历史，不改正常对话的工具、思考档位或 Fast。

## 计划模式
所有角色的会话都可以从输入框工具栏、审批档位选择器旁打开「计划模式」，只有派发出的 worker 会话没有这个开关。开关按会话保存，新会话默认关闭，重启、归档后恢复都保持；运行中也能切换，主 agent 的派发拦截立即生效，提示词从下一轮运行起变化。
计划模式用来写计划和文档。文档指扩展名为 `.md` / `.markdown`（不分大小写）的 Markdown 文件；代码、配置和其他任何文件在计划模式下都不会被改。
计划文件放在当前项目根目录下的 `.fynvra/plans/`，例如项目在 `D:\project\Agent-Forge` 时就是 `D:\project\Agent-Forge\.fynvra\plans\`，不是用户主目录。
主 agent（内置 Orchestrator，或工具策略为 orchestrator 的自定义角色）开启后专门写计划和文档、不派活。用户要写文档时，主 agent 用 `write_doc` 把 Markdown 文档直接写到用户指定的路径，可以在项目外（如桌面）；只能写 `.md` / `.markdown`，不会改代码或配置；写入按角色的审批档位处理（`supervised` 会询问）。计划模式关闭时 `write_doc` 不可用，文档和其他文件一样派给 worker 写。写计划时先读代码，再用 `write_plan` 把一份 Markdown 计划写到计划目录，包含目标、方案、任务拆分（每个任务的角色、文件归属、验收）、顺序与依赖、风险和不做的事；在回复里给出计划文件链接请用户审阅，按反馈更新同一份文件。此时派发新任务（`dispatch_task`）会被拒绝，已在跑的 worker 照常处理：回答、审查、合并、打回、清理。
其他角色开启后只做只读调查，用 `write_plan` 写计划，可以写入、编辑 Markdown 文档（按原审批档位处理），不能改其他文件：目标里只要有一个不是文档，写入、编辑、打补丁就拦下；只读的命令按原审批档位处理，不是只读的命令和 MCP 工具不论审批档位都要用户确认。只读判定偏保守：组合命令的每一段都得是白名单里的只读命令，含重定向、命令替换、脚本块的一律算非只读。`rm -rf`、`git push` 等保护底线不变。
用户在应用内打开计划文件预览或直接编辑；审阅通过后关闭计划模式即可执行：主 agent 先重读计划文件（用户可能改过），再按计划派发；其他角色不再受计划模式限制，按原审批档位改文件、跑命令。
计划文件和写进项目的文档都不会自动提交；未提交时 worker 的 worktree 里看不到它，所以任务书仍须完整自足。要不要提交，或在 `.gitignore` 里忽略 `.fynvra/`，由用户决定；没忽略时计划文件会出现在「改动」里，「全部丢弃」会删除这些未跟踪的计划文件。`write_plan` 只能写计划目录，所以不走文件写入审批；计划模式关闭时也能用，供用户要求书面计划时使用。

## 网页读取
所有角色（包括主 agent 和派发出的 worker）都有内置的 `web_fetch`：读取用户给定的公开网页链接，把正文转成 Markdown，并注明来源 URL、重定向和读到的范围；长页面分页继续读。网页内容被标记为不可信的数据，不是指令。
限制：只读文本网页（HTML、纯文本、JSON、XML / RSS 等），不渲染 JavaScript、不截图、不登录、不带 Cookie，也不做联网搜索；需要 JavaScript 渲染的页面可能只读到外壳，工具会如实提示；遇到 403、验证码、登录墙只如实报告。本机、内网和云元数据地址默认一律拒绝；在「设置 → 通用」开启「允许 web_fetch 访问本机地址」后（默认关闭，之后新加载的会话生效）只放行回环地址（localhost / 127.0.0.1 / ::1），如本地开发页面：URL 主机本身须是本机名或回环地址（公网域名解析到本机仍拒绝），公网页面不能重定向到本机，本机地址始终直连不走代理、不缓存，内网和云元数据地址仍拦截。PDF、图片等二进制内容不支持。
访问前走「访问网络」审批：全程审批、自动接受编辑两档都会询问并显示完整 URL，可选“本会话都允许”；完全放行档不问。
代理：复用「设置 → 通用 → 网络代理」，它作用于命令 / Git 子进程、网页读取与 Fynvra 插件的联网。默认跟随系统代理，和浏览器一致（如 Clash、v2rayN 的“系统代理”模式，不用任何设置）；连不上时检查 VPN，或在「设置 → 通用 → 网络代理」改用手动代理；系统代理是 SOCKS 时暂不支持，需改用手动代理填 HTTP 端口；Clash / Surge 的 TUN（fake-ip）模式不需要任何设置。设置或系统代理修改后新加载的会话才生效。

## 文件预览
右栏文件除文本、Markdown 和图片外，还能在应用内预览 PDF（连续页面、放大缩小、页数，支持中文）和 Word：`.docx` 按语义完整渲染（复杂排版如分栏、文本框、页眉页脚不还原），旧版 `.doc` 在装有 Microsoft Word 的 Windows 上由本机 Word 在后台转换（宏禁用、不碰原文件）后按 `.docx` 显示格式、表格和图片；没有 Word、转换失败或超时则只显示文字并注明原因。这三类文件最大 32 MiB，只读、不能编辑保存；只是应用内预览，AI 工具不会因此读取 Word / PDF 内容。
Markdown 文件默认以只读预览打开，可切换到源码编辑或双栏（源码 + 只读预览）。Markdown 预览和 Word 预览里按 Ctrl+F（macOS 为 Cmd+F）在右上角打开查找条：高亮全部匹配，Enter / Shift+Enter 上下跳转，Esc 关闭；源码模式用编辑器自带的搜索。PDF 暂不支持页内查找。标签很多时，可以在标签栏上直接滚动鼠标滚轮横向滚动。
聊天里的文件链接指向工作区内时在应用内打开；指向工作区外的文件（如插件生成的图片）时，点击会用系统默认应用打开图片、PDF、文本、音视频和 Office 文档，其他类型只在文件夹中显示、绝不运行；右键链接可以打开、在文件夹中显示或复制路径。

## 插件
插件分两类：
- **PI 插件**：pi 扩展或 pi 包，给 AI 加工具、命令和事件钩子，挂到角色上，在会话里生效。下面除「Fynvra 插件」一段外说的都是这一类。
- **Fynvra 插件**：给 Fynvra 本身加功能（例如官方的 Telegram 群反馈值班），每个插件在独立进程里常驻后台，可以有自己的设置页，只能通过 Fynvra 开放的宿主 API 做事，不挂角色。

**Fynvra 插件**：前期只有官方插件，从插件市场安装，装完即启用，可以停用、更新、移除；开发版可以从本地目录添加，用于调试。它在后台常驻运行，以你的权限执行代码，没有沙箱：Fynvra 的权限声明（通知、联网、工作区列表、渠道、设置页）只约束它通过 Fynvra 能做什么，管不住它直接读写文件或联网，所以只开放官方插件。插件反复崩溃（10 分钟内 3 次）会被自动停用并显示原因。

PI 插件就是 pi 扩展或 pi 包，给 agent 增加工具、命令和事件钩子，包里的技能与提示词模板随之加载；不含界面插件。
在「设置 → 插件」里添加：本地目录或扩展文件，或从 npm（`npm:<包名>[@版本]`）、git（`git:<host>/<path>[@ref]` 或 `https://` 仓库地址）安装，安装需要本机有 npm / git。可以启用、停用、移除。也可以「从本机导入」：扫描原生 pi 的 `~/.pi/agent/extensions/` 和 settings.json 里声明的包，勾选后一键导入（本地的复制，npm / git 的安装），已导入的标「已导入」。
插件统一存放在 `~/.fynvra/plugins/`（开发版 `~/.fynvra-dev/plugins/`），每个插件一个目录，npm / git 安装的也在这里。本地插件一律**复制一份**到这里，在 Fynvra 里改副本不影响原文件（如原生 pi 正在用的扩展）。详情显示插件当前所在的路径（副本路径，或 npm / git 的安装目录）；旧版添加的「引用」插件标出「引用」，仍可使用，可一键「转为副本」。「…」菜单可打开文件夹、用编辑器打开、作为工作区打开，副本可「从源文件重新复制」（覆盖对副本的修改）。移除插件会把它从使用它的角色中移除，并删除副本目录（旧引用只删登记，不删你的目录；npm / git 包会删除安装目录）；文件正被占用时插件照样移除，重启 Fynvra 后自动清理剩余文件。卡片还显示插件需要的模型服务（插件运行时按名查找过的服务名），每个名字可下拉选择实际使用的服务，默认使用同名服务；改选对新会话生效。添加时扫描代码识别所需服务，识别不到可手动添加；未找到的服务可直接新建。
**插件市场**：在「设置 → 插件 → 市场」里浏览和安装。市场只上架审核过的插件，分「官方」和「已审核」两档；索引有签名、插件包有哈希校验，安装时不运行包里的任何脚本（依赖已预先打包）。有新版本时只提示，由你决定是否更新，不自动更新。某个版本发现问题会被远程撤回：已安装的会被自动停用并弹出通知说明原因。市场插件同样以你的权限运行，没有沙箱。想上架自己的插件，去注册表仓库 `LAIJiangFeng/fynvra-plugins` 提 PR 或 Issue。
**插件页界面**：「设置 → 插件」分「已安装」「市场」两个标签。
- 已安装：只有两块：上面是「Fynvra 插件」，下面是「PI 插件」，都以卡片网格展示（宽屏三列，窄屏自动变为两列、一列）：卡片顶部是图标、名称和徽标，中间最多两行简介，底部左边是作者，右边是更新按钮、启用开关和「…」菜单。Fynvra 插件卡片显示名称、简介（取自插件清单或市场）、版本、分级（本地安装的标「本地」）、状态（启动中 / 运行中 / 已停止 / 已崩溃，出错时显示原因）和撤回提示，可以启用 / 停用、更新（有新版时）、删除（需确认），本地安装的还能「从源目录重新复制」；声明了设置页权限且已启用的插件，点卡片或菜单里的「设置」在插件页内显示它的设置页，顶部「返回插件」。开发版在这个区还有「添加本地 Fynvra 插件（开发）」。PI 插件卡片的简介依次取市场、目录插件的 package.json、单文件插件开头的注释（只读文本，不执行代码），都没有时显示「暂无简介 · 文件或目录名」；简介被截断时悬停卡片可看全文。PI 插件卡片：点卡片进入详情（顶部「返回插件」），详情里有完整路径和来源、模型服务配置和删除；用到模型服务的卡片上提示「用到 N 个模型服务」；市场插件另外显示版本号和分级徽标（官方 / 已审核）；有新版本时显示「有更新 x.y.z」和「更新」按钮，更新不改启用状态和角色挂载；已被撤回的用红字提示「已被撤回：原因，已自动停用」。
- Fynvra 插件的设置页由插件声明、Fynvra 用自己的界面组件显示（分组、文字、键值、输入框 / 密码框 / 数字 / 开关 / 下拉、按钮、列表），插件代码不在界面里运行。开关和下拉改了立即保存，文字和数字在离开输入框或按回车时保存；密码框不显示已保存的值；危险按钮先确认；操作进行中按钮不可点，失败时显示插件返回的原因；列表里的链接只接受 https，在系统浏览器打开。插件停止后设置页清空，重新运行后由插件重新提供。
- 市场：顶部是「刷新」按钮、上次更新时间和错误提示；首次进入时缓存为空或超过 1 小时会自动刷新一次。市场尚未配置时只显示说明，不显示列表。可按名称、简介、标签搜索（不区分大小写）并按分类筛选。插件以同样的卡片网格展示，卡片显示名称、分级、类别（Fynvra 插件 / PI 插件）、作者、简介和最新版本，按钮为「安装」「已安装」「更新」，没有兼容版本时为「需要更新 Fynvra」。
- 详情：点卡片在插件页内打开，顶部「← 返回市场」。显示 README（不加载远程图片，图片显示为链接文字）、版本、发布时间、更新日志、许可证、源码仓库和主页链接（在系统浏览器打开），以及声明的权限：联网、读写文件、执行命令、读取环境变量、使用你的模型服务和密钥。
- 安装确认：醒目的风险提示、分级说明、声明的权限（声明只是作者自述），以及「安装后挂到这些角色」多选（默认不勾，之后新打开的该角色会话才能用）。Fynvra 插件不挂角色，没有这个多选；风险提示为「Fynvra 插件会在后台常驻运行，以你的权限执行代码，Fynvra 无法限制它。目前只提供官方插件」，权限显示为发桌面通知、联网、读取工作区列表、创建受限的分诊 / 值班会话并回复外部消息、设置页。安装成功后把插件挂到所选角色并关闭对话框；失败时在对话框里显示错误。
**信任提示**：插件会以你的用户权限执行任意代码，只安装可信来源。审批只管插件工具的调用，管不住插件加载时和钩子里的代码。
和原生 pi 一样，插件可以按服务 id（如 `sub2api`）找到已启用的模型服务，并读取它的地址和密钥；只对挂了插件的会话开放。
用法：在角色编辑器里为角色勾选插件（和 MCP 一样按角色挂载），之后新加载的该角色会话即可使用。插件工具调用走「插件工具」审批：全程审批、自动接受编辑两档询问，完全放行档不问，计划模式下不论档位都要确认。不做自动更新和沙箱。

## 工作流
在「设置 → 工作流」里用流程图把一个任务拆成多个角色节点（最多 20 个）：每个节点配名称、执行角色、本节点说明，以及失败时退回到哪个节点（只能是自己或上游节点）；节点之间连线表示先后依赖，一个节点的所有上游都通过后它才开始，没有依赖关系的节点可以同时进行。画布上拖动连线建立依赖（不允许成环），失败退回用红色虚线标出，可一键自动排版；列表里每个工作流显示一行文字摘要，如「开发 → (测试 ‖ 安全审查) → 验收」。工作流还有回退上限（0–10，默认 3）。画布右侧面板编辑选中节点，并只读列出它的上下游；删除节点时同时清理其他节点对它的依赖和失败退回。新建时可选空白或预设模板：「开发 → 测试 → 审核」（测试或审核不通过就退回开发），以及「开发 → (测试 ‖ 安全审查) → 验收」（测试与安全审查并行，任一不通过或验收不通过都退回开发）。编排类角色不能当节点角色。以前保存的按顺序排列的工作流自动视为一条直线流程。
对主 agent 说「用 <工作流> 做 X」即可，由 Fynvra 自动推进：一个任务最多同时运行 4 个节点；git 工作区里同时运行的节点各自在独立的 worktree 里工作，完成后依次合并回任务的集成 worktree，合并冲突算该节点失败；普通目录一次只运行一个节点。有节点报告失败时不再启动新节点，等运行中的节点结束后汇总：失败的节点都设置了退回且未超过回退上限，就带着全部问题退回最上游的退回目标，从那里重新往下走；否则把任务记为失败并告诉主 agent。任务面板用同样的流程图显示进度，按节点状态着色，点击节点可查看对应 worker 的输出。对话里的派发卡片也实时显示工作流进度（整体状态、小流程图和逐节点说明），点击节点直接在任务面板打开它的输出。
全部节点通过后，主 agent 照常看集成 worktree 的差异、跑检查、验收合并；主 agent 打回时从起点节点开始整张图重跑，放弃任务时停掉所有节点并清理全部 worktree。不做条件分支（除失败退回外）、跨任务工作流和节点级模型设置。

## Telegram 群反馈值班
官方 Fynvra 插件（`com.fynvra.telegram`），从插件市场安装；开发版可从本地目录安装（「添加本地 Fynvra 插件（开发）」）。Fynvra 本身不再内置它。群成员在 Telegram 群里报 bug、提需求，Fynvra 在电脑上分诊：已定位的 bug 自动修复并开 PR，新功能先评估、再由你在电脑上确认。
- **只做电脑端**：Telegram 只用作群消息通道，没有私聊、手机确认或手机通知；你的所有操作都在电脑上的 Fynvra 里完成。
- **怎么用**：
  - 安装后在「设置 → 插件 → 已安装」的 Fynvra 插件区点它的「设置」，填 Bot Token（在 @BotFather 用 `/newbot` 获取）；以前用过内置版的，插件首次运行时自动导入原来的 token、群和记录；
  - 把机器人拉进群，在群里 @机器人 发一条消息，这个群就会出现在候选群里；允许它并绑定一个 git 工作区；
  - 群成员在群里 @机器人 提问、闲聊或描述问题（也支持 `/bug@机器人 描述`），或回复机器人的消息；其余群消息直接丢弃、不保存；
  - 群里发的图片和文档按聊天输入框同样的规则处理（格式与上限见「输入框附件」），不支持或超限的不会发给模型；
  - @ 了机器人没有反应时：在 @BotFather 用 `/setprivacy` 关闭隐私模式，再把机器人移出群、重新拉进来；
  - Fynvra 关着时不工作；开 PR 需要本机装好 `gh` 并登录，仓库的 `origin` 可以 push；网络跟随「设置 → 通用 → 网络代理」。
- **安全**：
  - 分诊会话只能读本项目已提交的代码并回群；修复在受限的 worker 里进行，只在本项目的 worktree 里改代码，不能联网、不执行项目代码，本机只跑 typecheck 和 lint；这些命令的环境变量里不带你的密钥。
  - 值班想在本机跑测试时会弹出确认，你同意才跑；拒绝或 10 分钟不处理就不跑，测试交给 PR 的 Checks。
  - 群回复和推送都经 Fynvra 的确定性过滤：含密钥就整条拦下，本机路径和用户名会被替换；推送前还要过推送闸门（保护路径、密钥扫描、本机路径）。
  - **Fynvra 只开 PR，从不合并**，合不合并由你决定；新功能你点「采纳」之前不动代码。
  - 只动已挂入 Fynvra、且已绑定到群的工作区；除了上面的本机跑测试，这些会话不会等你审批（审批档位显示「自动执行（规则把关）」，不可切换）。
  - 插件以你的权限在后台运行，没有沙箱，所以只提供官方插件。

## 外观
「设置 → 外观」有主题、界面、终端三组，全部即时生效，不用重启；「界面」「终端」各有「恢复默认」。
- 主题：浅色 / 深色 / 跟随系统，与标题栏的主题菜单一致。
- 界面：字体（CSS font-family 列表，留空用内置字体栈）、字号（正文字号 12–24 px，默认 14，整个界面按比例缩放，文件编辑器也随之缩放）、字重（正文的默认字重，单独设了字重的文字不变）。代码块、diff 这类等宽内容仍用等宽字体。
- 终端：配色方案（内置 Fynvra、0x96f、Dracula、One Dark、Nord、Gruvbox Dark、Tokyo Night、Catppuccin Mocha、Solarized Dark、Solarized Light、GitHub Light，默认 Fynvra）、字体（留空用 `Consolas, "Cascadia Mono", Menlo, monospace`）、字号（8–32 px，默认 14）、字重（默认 Normal）、粗体字重（默认 Bold）。新开和已打开的终端都按设置显示，字号或字体变了会重新适配行列数。

文本框与数字框在失焦或回车时保存，非法值不保存并恢复原值。不做界面配色方案（即主题）、界面粗体字重、自定义配色导入、按工作区区分的设置、代码块与 diff 的独立字体、快捷键缩放。

## 一句话用户旅程
挂入仓库 → 在该仓库开一个 Orchestrator 会话 → 说「做 X，Y 用测试工程师角色」→ 侧栏出现多个 worker 卡片（各自 worktree、实时输出、状态）→ 主 agent 验收合并 → 用户在自己的浏览器/终端验证效果。

## 工程与安全边界
- 分层构建：electron-vite 三段构建，结合 Zustand、Tailwind 4、Biome 与 Vitest；应用元数据通过 settings.json 持久化。
- 进程隔离：明确 IPC 与 Agent Worker 的安全边界，会话 jsonl 为正文权威源（见 `AGENTS.md`）。
- 资源配置：统一管理 Providers、Skills 与 MCP，支持扫描导入本机工具配置（模型服务可从 Claude Code、Codex、CC Switch、pi 导入；pi 中命令形式的 key 不会执行，需手动填写）。
- 对话里配置：用户在对话里要求时，主 agent 与 worker 可用 `fynvra_config` 安装技能并挂到角色、增改 MCP 服务器与工作流、安装 / 启停插件、调整角色的技能，效果与在「设置」里操作相同；改动按会话审批档位确认，密钥值不回显。
- 任务验收：内置差异查看、三档审批与 worktree 验收合并流程。
