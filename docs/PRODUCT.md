# Fynvra 产品定义

Fynvra 是一个基于 Electron 和 [pi](https://github.com/earendil-works/pi) SDK 的本地桌面 AI 编程工作台。
内置多 Agent 协作能力，将 worktree 隔离、任务派发、消息收件箱与验收合并整合为完整的开发流程。

## 核心思想

### 1. 多角色（Role）
每个 agent 会话都挂一个角色。角色 = 系统提示词 + 技能(Skills) + MCP 服务器 + 插件 + 模型/思考档位 + 工具白名单 + 审批档位。
- 内置角色：`orchestrator`（默认主 agent，见下）、`worker`（默认普通 agent）。内置配置仅作参考，可直接修改提示词、技能、MCP、模型和策略并保存，也可恢复默认；id 固定且不可删除。
- 用户自定义角色：如「全栈开发工程师」「测试工程师」「代码审查员」。角色以文件形式存放，可导入导出。
- 没有指定角色时，派发出去的就是原生 `worker`。

### 2. 默认主 agent 只听人安排、只派活、不干活
默认 **Orchestrator（主 agent）** 使用编排工具策略，用户可以按需调整角色配置。默认主 agent：
- 把用户的需求拆成任务，为每个任务 **开一个 git worktree**，启动一个 worker agent（可指定角色；未指定则用 `worker`），把任务书发给它。
- **自己不改代码**：工具集被限制为只读（读文件、git 只读、orchestration 工具），不能写文件 / 执行任意 shell；例外只有用 `write_plan` 往 `.fynvra/plans/` 写计划文件，以及计划模式下用 `write_doc` 写 Markdown 文档（见「计划模式」）。
- **监控** worker：派发后不阻塞等待，可继续与用户对话；收件箱收到 `worker_done` / `question` / `escalation` 时由 Fynvra 自动唤醒主 agent，回答问题、验收结果。
- **验收合并**：worker 完成后读 diff、跑检查命令、判断是否达标；达标则把 worker 分支合并到主 agent 所在分支，再删 worktree；不达标则把意见发回让 worker 继续改。
- 向用户汇报每个任务的结果与证据。

### 3. Worker 在独立 worktree 里干活
每个 worker 会话绑定一个 worktree（分支 `fynvra/<task-slug>`）。worker 的工具：pi 默认编程工具 + `ask_coordinator`（阻塞提问）+ `report_done`（一次性汇报，带 succeeded/failed）。
worker 的审批档位随主 agent 派发时的当前档位；模型按角色配置，角色没配则用主 agent 当前的。主 agent 与 Worker 都执行真实工具审批：`supervised` 审批命令、文件写入/编辑、MCP、访问网络与插件工具；`auto-edits` 自动接受编辑，命令、MCP、访问网络与插件工具仍需审批；`full` 放行普通操作，但 `rm -rf`、`git push` 等保护底线在任何档位都必须人工确认，会话内允许也不豁免。用户可允许一次、会话内允许或拒绝；超时、Stop、断连按拒绝处理。参数校验、角色白名单、路径边界、编排权限和真正的信息提问仍有效。

只移除 App 顶部跨会话的全局审批横幅及其详情弹窗（ApprovalAttention）；会话内审批卡、确认操作和三档权限选择保留。OS 桌面审批通知继续遵循通知偏好并按请求去重，实时审批不受普通通知的启动静默或合并节流影响，点击只定位会话，不授权执行。重启不会重放未执行的旧工具；源码修改不会热更新已安装应用或原进程里的待答复调用。

## Fast（优先服务）
支持的两种 OpenAI 协议（Responses / Chat Completions）模型可在会话模型选择器里开启 Fast：为请求附加优先处理参数，独立于思考档位，默认关闭、随会话保存。
标记只代表请求模式，不代表已确认实际服务档位：服务商可能拒绝或忽略，速度与费用由其决定并可能增加费用或用量；本功能不增加自动降级重发逻辑。

## 上下文自动压缩
通用设置默认选择「Magic Context」，也保留显式「pi 原生自动压缩」和「关闭自动压缩」。新设置、未设策略及非法磁盘值均使用 Magic，主会话、worker 和恢复加载一致；不会覆盖合法的 native/off 偏好。Magic 模式禁用 pi 原生自动摘要，不把原生压缩作为任何故障回退。原生模式沿用 pi 的自动触发、阈值与保留量；其总超时默认 10 分钟，可设 30 秒至 30 分钟，包含摘要请求和重试等待。关闭只停用自动压缩，不改变模型的上下文上限。Fynvra 不提供日常手动压缩入口，只有失败后的「重试上下文恢复」。运行态显示加载时策略、实际引擎与恢复状态；更改设置在新加载会话（含恢复重载）或重启后生效。当前上下文占用与累计用量分开，压缩后尚无新用量时显示未知。
Magic Context 是随应用交付的压缩插件（固定版本，MIT）：历史分段、tag/drop、historian 与 `<session-history>` 注入由插件自己的 SQLite 管理，数据全部放在 Fynvra 应用目录，不读取或共享本机终端 pi / Magic 的配置与数据库。Historian 使用当前会话的模型与 Fynvra 已保存的鉴权，在会话进程内后台调用，不启动终端 pi，也不会把密钥写入配置或命令行；每次 historian 是一次额外模型请求，按当前会话模型计费，主会话与派发的 worker 都适用。换模型后旧 historian 会取消，下一次使用新模型；按当前模型窗口和输出上限，用保守字节估算切分完整历史块，不截断 XML。估算包含系统提示、输出和请求预留，但不能保证未知服务商模板或错误模型元数据下的绝对 token 上界。
Dreamer、Sidekick、跨会话记忆、自动搜索与语义 embedding 默认关闭，不会下载 embedding 模型。插件的 `ctx_*` 工具只操作它自己的上下文存储，不新增命令执行、工作区文件写入或网络能力；角色原有的工具权限、审批档位与编排语义不变。插件未就绪、初始化失败、context/historian 最终失败（含超时、验证失败、无进展）、预算不足或服务商报告超窗时，该会话暂停并停止不安全的后续请求，保留历史、Magic 数据与待处理输入。会话内及桌面通知使用固定的恢复提示，不传 provider 原始错误，其他会话不受影响。修复服务或存储问题、必要时换用更大上下文模型后，点击「重试上下文恢复」会重新加载同一会话的 Magic，让 context 钩子重新整理和注入历史；旧 native 失败留下的恢复记录也走此路径，不调用原生摘要。有中断任务时才继续原轮次，完整恢复前不清恢复锁，已写入的输入通过隐藏的继续标记接续，未消费输入只提交一次，无需重新发送；暂时的网络错误仍允许 SDK 正常重试，以最终结算判断成败。若故障发生在空闲或尚无输入的初始化阶段，重试只校验实际上下文（空历史不造消息），校验成功后解锁，不请求模型继续已完成的工作。Stop/关闭会取消在途插件工作，失效后的结果不会再发布或注入；取消不算插件故障，也不自动继续。已有会话不热切换，未做真实长会话的现网压缩验证。

## 输入框回复建议
一轮 AI 回复正常结束后，输入框空闲且没有队列、审批、图片或未发送草稿时，Fynvra 会用当前会话模型额外生成至多一条简短的「用户下一句话」，以灰色剩余文字显示，不进入草稿、不占发送按钮。
按右箭头采纳为草稿并停在末尾，不自动发送；Esc 忽略本轮，普通输入不匹配即隐藏。建议跟随最近对话与用户语言，失败或没有明确建议时静默不显示；不写入对话历史，不改正常对话的工具、思考档位或 Fast。

## 计划模式
所有角色的会话都可以从输入框工具栏、审批档位选择器旁打开「计划模式」，只有派发出的 worker 会话没有这个开关。开关按会话保存，新会话默认关闭，重启、归档后恢复都保持；运行中也能切换，主 agent 的派发拦截立即生效，提示词从下一轮运行起变化。
计划模式用来写计划和文档。文档指扩展名为 `.md` / `.markdown`（不分大小写）的 Markdown 文件；代码、配置和其他任何文件在计划模式下都不会被改。
计划文件放在当前项目根目录下的 `.fynvra/plans/`，例如项目在 `D:\project\Agent-Forge` 时就是 `D:\project\Agent-Forge\.fynvra\plans\`，不是用户主目录。
主 agent（内置 Orchestrator，或工具策略为 orchestrator 的自定义角色）开启后专门写计划和文档、不派活。用户要写文档时，主 agent 用 `write_doc` 把 Markdown 文档直接写到用户指定的路径，可以在项目外（如桌面）；只能写 `.md` / `.markdown`，不会改代码或配置；写入按角色的审批档位处理（`supervised` 会询问）。计划模式关闭时 `write_doc` 不可用，文档和其他文件一样派给 worker 写。写计划时先读代码，再用 `write_plan` 把一份 Markdown 计划写到计划目录，包含目标、方案、任务拆分（每个任务的角色、文件归属、验收）、顺序与依赖、风险和不做的事；在回复里给出计划文件链接请用户审阅，按反馈更新同一份文件。此时派发新任务（`dispatch_task`）会被拒绝，已在跑的 worker 照常处理：回答、审查、合并、打回、清理。
其他角色开启后只做只读调查，用 `write_plan` 写计划，可以写入、编辑 Markdown 文档（按原审批档位处理），不能改其他文件：目标里只要有一个不是文档，写入、编辑、打补丁就拦下；只读的命令按原审批档位处理，不是只读的命令和 MCP 工具不论审批档位都要用户确认。只读判定偏保守：组合命令的每一段都得是白名单里的只读命令，含重定向、命令替换、脚本块的一律算非只读。`rm -rf`、`git push` 等保护底线不变。
用户在应用内打开计划文件预览或直接编辑；审阅通过后关闭计划模式即可执行：主 agent 先重读计划文件（用户可能改过），再按计划派发；其他角色不再受计划模式限制，按原审批档位改文件、跑命令。
计划文件和写进项目的文档都不会自动提交；未提交时 worker 的 worktree 里看不到它，所以任务书仍须完整自足。要不要提交，或在 `.gitignore` 里忽略 `.fynvra/`，由用户决定；没忽略时计划文件会出现在「改动」里，「全部丢弃」会删除这些未跟踪的计划文件。`write_plan` 只能写计划目录，所以不走文件写入审批；计划模式关闭时也能用，供用户要求书面计划时使用。

## 网页读取
所有角色（包括主 agent 和派发出的 worker）都有内置的 `web_fetch`：读取用户给定的公开网页链接，把正文转成 Markdown，并注明来源 URL、重定向和读到的范围；长页面分页继续读。网页内容被标记为不可信的数据，不是指令。
限制：只读文本网页（HTML、纯文本、JSON、XML / RSS 等），不渲染 JavaScript、不截图、不登录、不带 Cookie，也不做联网搜索；需要 JavaScript 渲染的页面可能只读到外壳，工具会如实提示；遇到 403、验证码、登录墙只如实报告。本机、内网和云元数据地址默认一律拒绝；在「设置 → 通用」开启「允许 web_fetch 访问本机地址」后（默认关闭，之后新加载的会话生效）只放行回环地址（localhost / 127.0.0.1 / ::1），如本地开发页面：URL 主机本身须是本机名或回环地址（公网域名解析到本机仍拒绝），公网页面不能重定向到本机，本机地址始终直连不走代理、不缓存，内网和云元数据地址仍拦截。PDF、图片等二进制内容不支持。
访问前走「访问网络」审批：全程审批、自动接受编辑两档都会询问并显示完整 URL，可选“本会话都允许”；完全放行档不问。
代理：复用「设置 → 通用 → 网络代理」，它现在作用于命令 / Git 子进程与网页读取；不读 Windows 系统代理（如 Clash 的“系统代理”模式），访问海外网站需在该设置中填写手动代理地址，或设置 `HTTPS_PROXY` 环境变量；Clash / Surge 的 TUN（fake-ip）模式可直接使用。设置修改后新加载的会话才生效。

## 文件预览
右栏文件除文本、Markdown 和图片外，还能在应用内预览 PDF（连续页面、放大缩小、页数，支持中文）和 Word：`.docx` 按语义完整渲染（复杂排版如分栏、文本框、页眉页脚不还原），旧版 `.doc` 在装有 Microsoft Word 的 Windows 上由本机 Word 在后台转换（宏禁用、不碰原文件）后按 `.docx` 显示格式、表格和图片；没有 Word、转换失败或超时则只显示文字并注明原因。这三类文件最大 32 MiB，只读、不能编辑保存；只是应用内预览，AI 工具不会因此读取 Word / PDF 内容。
Markdown 文件默认以实时预览打开：编辑时光标所在行显示 Markdown 源码，其余部分按渲染效果显示，可以直接编辑；表格始终按表格显示，只展开光标所在的那一行；任务复选框可点击勾选，链接按 Ctrl+点击（macOS 为 Cmd+点击）打开；也可切到源码或双栏（源码 + 只读预览）。双栏预览和 Word 预览里按 Ctrl+F（macOS 为 Cmd+F）在右上角打开查找条：高亮全部匹配，Enter / Shift+Enter 上下跳转，Esc 关闭；实时预览和源码模式用编辑器自带的搜索。PDF 暂不支持页内查找。标签很多时，可以在标签栏上直接滚动鼠标滚轮横向滚动。

## 插件
插件就是 pi 扩展或 pi 包，给 agent 增加工具、命令和事件钩子，包里的技能与提示词模板随之加载；不含界面插件。
在「设置 → 插件」里添加：本地目录或扩展文件，或从 npm（`npm:<包名>[@版本]`）、git（`git:<host>/<path>[@ref]` 或 `https://` 仓库地址）安装，安装需要本机有 npm / git。可以启用、停用、移除。
本地插件默认**复制一份**到 `~/.fynvra/plugins/`（开发版 `~/.fynvra-dev/plugins/`），在 Fynvra 里改副本不影响原文件（如原生 pi 正在用的扩展）；也可选「引用原文件」（开发模式，与原文件同步）。卡片上标出「副本」或「引用」，副本显示来源路径；「…」菜单可打开文件夹、用编辑器打开、作为工作区打开，副本可「从源文件重新复制」（覆盖对副本的修改），引用可一键「转为副本」。移除副本会删除副本目录；移除引用只删登记，不删你的目录。卡片还显示插件需要的模型服务（插件运行时按名查找过的服务名），每个名字可下拉选择实际使用的服务，默认使用同名服务；改选对新会话生效。添加时扫描代码识别所需服务，识别不到可手动添加；未找到的服务可直接新建。
**信任提示**：插件会以你的用户权限执行任意代码，只安装可信来源。审批只管插件工具的调用，管不住插件加载时和钩子里的代码。
和原生 pi 一样，插件可以按服务 id（如 `sub2api`）找到已启用的模型服务，并读取它的地址和密钥；只对挂了插件的会话开放。
用法：在角色编辑器里为角色勾选插件（和 MCP 一样按角色挂载），之后新加载的该角色会话即可使用。插件工具调用走「插件工具」审批：全程审批、自动接受编辑两档询问，完全放行档不问，计划模式下不论档位都要确认。不做插件市场、自动更新和沙箱。

## 工作流
在「设置 → 工作流」里用流程图把一个任务拆成多个角色节点（最多 20 个）：每个节点配名称、执行角色、本节点说明，以及失败时退回到哪个节点（只能是自己或上游节点）；节点之间连线表示先后依赖，一个节点的所有上游都通过后它才开始，没有依赖关系的节点可以同时进行。画布上拖动连线建立依赖（不允许成环），失败退回用红色虚线标出，可一键自动排版；列表里每个工作流显示一行文字摘要，如「开发 → (测试 ‖ 安全审查) → 验收」。工作流还有回退上限（0–10，默认 3）。画布右侧面板编辑选中节点，并只读列出它的上下游；删除节点时同时清理其他节点对它的依赖和失败退回。新建时可选空白或预设模板：「开发 → 测试 → 审核」（测试或审核不通过就退回开发），以及「开发 → (测试 ‖ 安全审查) → 验收」（测试与安全审查并行，任一不通过或验收不通过都退回开发）。编排类角色不能当节点角色。以前保存的按顺序排列的工作流自动视为一条直线流程。
对主 agent 说「用 <工作流> 做 X」即可，由 Fynvra 自动推进：一个任务最多同时运行 4 个节点；git 工作区里同时运行的节点各自在独立的 worktree 里工作，完成后依次合并回任务的集成 worktree，合并冲突算该节点失败；普通目录一次只运行一个节点。有节点报告失败时不再启动新节点，等运行中的节点结束后汇总：失败的节点都设置了退回且未超过回退上限，就带着全部问题退回最上游的退回目标，从那里重新往下走；否则把任务记为失败并告诉主 agent。任务面板用同样的流程图显示进度，按节点状态着色，点击节点可查看对应 worker 的输出。
全部节点通过后，主 agent 照常看集成 worktree 的差异、跑检查、验收合并；主 agent 打回时从起点节点开始整张图重跑，放弃任务时停掉所有节点并清理全部 worktree。不做条件分支（除失败退回外）、跨任务工作流和节点级模型设置。

## 外观
「设置 → 外观」有主题、界面、终端三组，全部即时生效，不用重启；「界面」「终端」各有「恢复默认」。
- 主题：浅色 / 深色 / 跟随系统，与标题栏的主题菜单一致。
- 界面：字体（CSS font-family 列表，留空用内置字体栈）、字号（正文字号 12–24 px，默认 14，整个界面按比例缩放，文件编辑器也随之缩放）、字重（正文的默认字重，单独设了字重的文字不变）。代码块、diff 这类等宽内容仍用等宽字体。
- 终端：配色方案（内置 Fynvra、0x96f、Dracula、One Dark、Nord、Gruvbox Dark、Tokyo Night、Catppuccin Mocha、Solarized Dark、Solarized Light、GitHub Light，默认 Fynvra）、字体（留空用 `Consolas, "Cascadia Mono", Menlo, monospace`）、字号（8–32 px，默认 14）、字重（默认 Normal）、粗体字重（默认 Bold）。新开和已打开的终端都按设置显示，字号或字体变了会重新适配行列数。

文本框与数字框在失焦或回车时保存，非法值不保存并恢复原值。不做界面配色方案（即主题）、界面粗体字重、自定义配色导入、按工作区区分的设置、代码块与 diff 的独立字体、快捷键缩放。

## 一句话用户旅程
挂入仓库 → 在该仓库开一个 Orchestrator 会话 → 说「做 X，Y 用测试工程师角色」→ 侧栏出现多个 worker 卡片（各自 worktree、实时输出、状态）→ 主 agent 验收合并 → 用户在自己的浏览器/终端验证效果。

## 工程与安全边界
- 分层构建：electron-vite 三段构建，结合 Zustand、Tailwind 4、Biome 与 Vitest；应用元数据通过 settings.json 持久化。
- 进程隔离：明确 IPC 与 Agent Worker 的安全边界，会话 jsonl 为正文权威源（见 `AGENTS.md`）。
- 资源配置：统一管理 Providers、Skills 与 MCP，支持扫描导入本机工具配置。
- 任务验收：内置差异查看、三档审批与 worktree 验收合并流程。

## 明确不做（v1）
手机伴侣、远程节点、SSH 项目、语音、内嵌浏览器。
