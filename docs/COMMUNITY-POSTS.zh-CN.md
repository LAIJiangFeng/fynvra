## AI 社区论坛

**推荐标题：** 做了一个开源的多 Agent 编程工作台：拆任务、并行执行、审查合并

**可复制正文：**

```text
大家好，最近我在开发一个开源项目 Fynvra，想分享给平时用 AI 写代码的朋友。

它是一个本地桌面 AI 编程工作台。我想把从提需求、拆任务到查看改动、审查合并的过程放在一起，让多 Agent 协作的进展更容易看清楚。

在 Git 仓库里，基本流程是这样的：

1. 把需求交给主 Agent，由它拆分任务并派给 Worker。
2. Worker 在各自独立的 Git worktree 中执行，适合并行的任务可以同时推进。
3. Worker 完成后，由主 Agent 审查改动、执行检查；通过后再合并，需要修改的任务可以打回继续处理。

工作台里整合了对话、编辑器和终端，也支持配置模型、角色、Skills 和 MCP，可以按自己的工作习惯安排不同角色与工具。

长对话中的上下文压缩和重试也有进度提示。压缩失败或超时后，会停下当前这一轮，保留历史和尚未处理的输入；需要手动选择「重试压缩」，成功后才恢复执行。

目前项目还在持续完善，官网和中英文文档已经上线。如果你也在用 AI 做开发，欢迎找一个小任务试试。我尤其想听听实际使用时遇到的困难：哪些配置不好理解、哪里看不清任务进度，或者审查和合并时有什么不顺手的地方。

官网：https://jfengl.cn/
快速开始：https://jfengl.cn/zh/docs/quickstart/
GitHub：https://github.com/LAIJiangFeng/fynvra

如果试用后觉得好用，欢迎到 GitHub 点个 ⭐ Star，感谢支持！也欢迎提 Issue 和建议。
```

## 素材建议（不属于发布正文）

- 推荐准备一段 30–60 秒的真实任务演示，加 2–3 张截图：工作台全景、Worker 协作、审查改动或最终成果。选一个容易看懂的小任务即可。
- 45 秒视频参考节奏：0–5 秒先展示结果 → 5–13 秒展示需求输入与拆任务 → 13–25 秒展示 Worker 并行执行 → 25–37 秒展示审查、检查与合并 → 37–45 秒回到成果，展示官网和 GitHub 地址。
- 等待过程可以加速，画面上标明「等待过程已加速」；关键输入、改动和结果留出阅读时间，避免让剪辑后的时长看起来像实际运行耗时。
- 截图和字幕以手机上能读清为准，适当放大关键区域；录制前隐藏账号、密钥和私人内容。
- 如果使用官网示意动画，明确标注「流程演示」，不能当作真实跑任务的录像。素材制作完成后再按实际内容补充配文。
